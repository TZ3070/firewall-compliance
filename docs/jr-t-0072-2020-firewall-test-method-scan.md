# JR/T 0072—2020 防火墙测评方法扫描结果

## 1. 结果概览

本次扫描以 `JR/T 0072—2020《金融行业网络安全等级保护测评指南》` 为来源，仅保留能够映射到 `JR/T 0071.2—2020` 防火墙候选控制的测评单元。

整理结果：

- 指南全文解析：1,290 个测评单元；
- 防火墙相关测评单元：283 个；
- 控制—测评单元关系：291 条；
- 已覆盖上一份目录中的全部 63 个控制；
- 第二级：63 个单元；
- 第三级：102 个单元；
- 第四级：118 个单元；
- 自动映射后需要人工复核：3 个单元。
- 源文档测评单元编号异常：1 处。

测评单元数量大于控制数量，是因为一个逻辑防火墙控制可能对应多个等级、多个要求项以及多个场景测评单元。

数据状态为 `Candidate`。正式使用前需要测评人员复核映射，并在版本化目录中绑定指南 verbatim 原文；只有通过审核的记录才可标记为 `citation_eligible=true`。

## 2. 与 JR/T 0071.2—2020 的关系

| 数据 | 作用 |

| JR/T 0072 测评方法目录 | 回答“检查什么对象、怎么检查、如何判定” |

每个 JR/T 0072 测评单元保存：

```text

```

正文印刷页码与当前 PDF 的关系为：

```text

```

目录中的页码是测评单元起始页码；测评步骤跨页时，应继续读取同一 `measurement_unit_id` 的完整文本。

## 3. 测评单元编号

指南附录 C 规定测评单元编号形如：

```text
L3-ABS1-04
```

含义为：

- `L3`：第三级；
- `ABS`：安全区域边界；
- `1`：安全测评通用要求场景；
- `04`：该类要求项的顺序编号。

本次使用的主要类别：

| 缩写 | 含义 |
|---|---|
| CNS | 安全通信网络 |
| ABS | 安全区域边界 |
| CES | 安全计算环境 |
| SMC | 安全管理中心 |

场景数字：`1` 为通用，`2` 为云计算，`3` 为移动互联，`4` 为物联网。

## 6. 示例：默认拒绝如何测评

对于 `JR0071-2-FW-007`，目录关联第二、第三、第四级相应的访问控制测评单元。典型步骤包括：

1. 核查边界或区域之间是否部署并启用访问控制设备；
2. 核查设备最后一条访问控制策略是否禁止所有网络通信；
3. 两项均为肯定才满足该测评单元，否则为部分符合或不符合。

因此系统不能只读取抽象字段：

```text
default_action = deny
```

还应验证规则顺序、末条规则和对应受控接口上的策略是否实际启用。

## 7. 示例：入侵防范如何测评

仅有：

```text
ips_enabled = true
```

不能直接输出 `Passed`。指南的测评步骤还可能要求：

- 验证端口扫描、暴力破解、木马后门、拒绝服务、缓冲区溢出、IP 碎片和蠕虫等攻击能否被检测；
- 检查规则库是否为最新版本；
- 检查策略是否覆盖所有关键网络节点；
- 检查攻击源、类型、目标、时间和告警信息；
- 对高等级要求执行内部攻击、新型攻击、APT 或联动处置验证。

缺少真实测试结果时，只能记录 `ConfigurationVerified`，最终结果应为 `NeedsReview`。

## 8. 搜索和执行流程

推荐查询流程：

1. 根据等保等级过滤 `classified_protection_level`；
2. 根据部署事实过滤 `context`；
3. 使用 JR/T 0071.2 控制 ID 取得对应测评单元；
4. 返回测评指标、测评对象、实施步骤和单元判定；
5. 根据 `assessment_methods` 调度配置解析、日志查询、文档取证或主动测试；
6. 每个步骤分别记录证据和结论；
7. 按原始 `decision_rule` 形成测评单元结果；
8. 再执行整体测评和风险分析，不能把单台设备结果直接作为系统级结论。

推荐的执行记录结构：

```json
{
  "measurement_unit_id": "L3-ABS1-02",
  "control_id": "JR0071-2-FW-007",
  "step_results": [
    {"step": 1, "result": "Passed", "evidence_ids": ["cfg-001"]},
    {"step": 2, "result": "Passed", "evidence_ids": ["cfg-002"]}
  ],
  "unit_result": "Passed",
  "reviewer": null
}
```

## 9. 单元结论和系统结论的边界

指南第 9、10 章要求按照以下顺序形成最终结论：

1. 完成单项测评单元判定；
2. 汇总一个安全控制点中的全部要求项；
3. 对部分符合或不符合项分析其他安全控制点是否具有补充作用；
4. 分析不同区域和访问控制路径是否存在补充控制；
5. 对剩余问题开展威胁利用可能性及业务、系统影响分析；
6. 结合风险、综合得分和阈值形成“符合、基本符合、不符合”。

所以：

```text
单台防火墙 Passed ≠ 等级保护对象整体符合
```

防火墙检测系统可以输出设备级 Finding、测评单元结果和证据完整性，但系统级等级测评结论需要整体测评和风险评价。

## 10. 三个需要人工复核的映射

| 测评单元 | 映射控制 | 原因 |
|---|---|---|
| L2-ABS3-07 | JR0071-2-FW-MOBILE-003 | 指南使用“鉴别密钥”，基本要求使用“认证密钥”，语义接近但措辞不同 |
| L3-CES1-03 | JR0071-2-FW-026 | 指南只写远程管理传输防窃听，基本要求 F3 还包含管理终端身份鉴别 |
| L4-ABS3-07 | JR0071-2-FW-MOBILE-003 | 同第二级无线密钥措辞差异 |

这些单元已标记：

```text
mapping_review_status = NeedsReview
```

在人工确认前不应直接进入正式自动规则包。

此外，源指南第四级移动互联章节 `8.3.3.3` 的第一个入侵防范单元仍印为 `L3-ABS3-03`，与第三级同名单元重复。目录没有擅自修改源编号，而是：

- 保留 `measurement_unit_id = L3-ABS3-03`；
- 按所在第 8 章归入第四级；
- 记录正确的印刷页 290、PDF 物理页 296；
- 映射至 JR/T 0071.2 第四级 `9.3.3.3 a)`；
- 在 `source_anomalies` 中显式登记。

因此测评单元不能只用原始编号作为数据库主键，应使用：

```text
classified_protection_level + guide_clause_id + measurement_unit_id + pdf_page_index
```

## 11. 不进入本目录的内容

- 封面、前言、目录、引言和规范性引用文件；
- 物理环境类测评；
- 安全制度、机构、人员和多数建设管理测评；
- 与防火墙没有直接证据关系的应用、数据库和个人金融信息测评；
- 大数据可参考安全评估方法；
- 测评力度表等方法论资料。

第 9、10 章虽然不生成防火墙配置规则，但已保留为最终结论边界和流程说明。

## 12. 产物使用方法

机器可读目录：

```text
backend/data/catalog/jr-t-0072-2020-firewall-test-methods.json
```

正式接入前需要：

1. 人工复核 3 个 `NeedsReview` 映射；
2. 为需要引用的测评单元补齐审核后的 verbatim 原文和稳定 Qdrant point ID；
3. 对配置核查步骤建立确定性字段规则；
4. 对日志、文档和主动测试步骤建立证据采集器；
5. 为单元判定建立逐步骤测试；
6. 将系统级结论保留给整体测评和风险分析模块。
